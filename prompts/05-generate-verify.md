Implement the generation and verification stages under pipeline/generate and pipeline/verify.

Generation: for each beat in a mission file, call retrieve() with the beat's facts_needed, then ask the LLM (behind an interface) to write N candidate lines (default 3) in the character's voice. The prompt must include: character voice and want, the beat gist, the sailing concept to express as a reaction (never as a lecture), the retrieved chunks with IDs, hard rules (1 to 3 short sentences, at most 40 words; use only facts present in the chunks; invented colour is allowed only if marked fictional; no dates or numbers unless in a chunk; no quotes from copyright-cite-only sources; respect the beat constraints). Output line records matching schema/line-record.schema.json with sources and fictional flags, in Portuguese first, then translate to en and fr in a separate call that must keep numbers and names unchanged.

Verification: a second, independent LLM call (fresh context) that receives only the line and the cited chunks and returns, per claim, supported / unsupported / contradicted with the chunk ID. Mark a line verified only when all claims are supported; otherwise status stays draft and the reasons are stored. Also run deterministic checks: schema validity, word limit, every number and year in the line appears in a cited chunk, flagged conflicts are not asserted as fact.

Write the results to lines/draft/*.json. Add a dry-run mode with a stub LLM for tests, plus tests for the verifier using one supported and one hallucinated example. Report the pass rate per mission.
